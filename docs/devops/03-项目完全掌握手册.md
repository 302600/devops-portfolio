## 第 1 章：地基——云服务器与远程操作

### 学什么
ECS、Rocky Linux、SSH、SSH 隧道、tmux。

### 为什么学
你所有东西都跑在一台租来的服务器上，这台机器怎么连、怎么让程序不断线、怎么安全访问内部服务——这是地基。

### 你项目里怎么用的

| 技术 | 你实际做了什么 |
|------|---------------|
| ECS | 买了阿里云 ECS，`ecs.e-c1m4.xlarge`，4核16G，100G 系统盘，按量付费 ¥0.93/小时，公网带宽 5Mbps |
| Rocky Linux | ECS 的操作系统，所有命令都在上面敲 |
| SSH | 用 SecureCRT 通过 SSH 连上 ECS，所有操作都在 SSH 会话里 |
| SSH 隧道 | 因为没备案，用 `ssh -L 9443:127.0.0.1:9443 root@公网IP` 把服务器端口映射到本地浏览器访问 |
| tmux | 跑耗时命令（装 K8s、拉镜像）时放进 tmux 会话，防止 SSH 断线前功尽弃 |

### 关键命令

```bash
# SSH 连接
ssh root@你的ECS公网IP

# SSH 隧道（本地 9443 → 服务器 9443）
ssh -L 9443:127.0.0.1:9443 root@公网IP

# tmux 常用
tmux new -s work          # 新建会话叫 work
tmux attach -t work       # 回到会话
tmux ls                   # 列出所有会话
# 会话里按 Ctrl+B 再按 D =  detach（离开但不中断）
```

### 坑点
- **备案拦截**：没备案的域名/IP 直接访问 HTTP 会被阿里云网关拦截。拦截依据是 HTTP 的 **Host 头域名**（不是端口），换端口没用。解法：SSH 隧道 + nip.io 域名（解析到 127.0.0.1），把 HTTP 封在 SSH 隧道里，网关读不到 Host 头。
- **带宽瓶颈**：5Mbps ≈ 640KB/s，拉大镜像会超时。解法：临时调高带宽峰值到 100Mbps（按流量计费，入向免费）。

2. tmux 解决什么问题？

## 第 2 章：容器三剑客——containerd / nerdctl / buildkit

### 学什么
镜像 vs 容器、Docker vs containerd、nerdctl 命令、镜像加速、buildkit 构建、Dockerfile 手写。

### 为什么学
容器是整个项目的核心。K8s 说到底就是"帮你自动管理成百上千个容器"的工具。

### 核心概念

**镜像 vs 容器**：镜像是只读模板（静的），容器是镜像跑起来的实例（动的）。一个镜像能跑多个容器。

**Docker vs containerd**：Docker 功能全但重。K8s 从 1.24 移除了 dockershim，直接用更轻的 containerd。Docker 底层本来也是 containerd。你项目里**卸掉了 Docker，用 containerd + nerdctl**。

### 你项目里的关键事实

**1. containerd 冲突（你踩过的坑）**
装 Sealos 时报错：系统里已有 containerd（是装 Docker 时带的 containerd.io），Sealos 要自己管理 containerd 拒绝复用。
**解法**：卸载 Docker + 清理残留目录 `/var/lib/docker`、`/var/lib/containerd`，重跑 Sealos 成功。

**2. 镜像加速要分三套配**
containerd、buildkit、Docker 是三个独立程序，加速要分别配：
```bash
# containerd 加速
mkdir -p /etc/containerd/certs.d/docker.io
cat > /etc/containerd/certs.d/docker.io/hosts.toml << 'EOF'
server = "https://docker.io"
[host."https://docker.m.daocloud.io"]
  capabilities = ["pull", "resolve"]
EOF

# buildkit 加速
mkdir -p /etc/buildkit
cat > /etc/buildkit/buildkitd.toml << 'EOF'
[registry."docker.io"]
  mirrors = ["docker.m.daocloud.io"]
EOF

# containerd 命名空间（关键！K8s 镜像在 k8s.io，nerdctl 默认看 default）
cat >> /etc/nerdctl/nerdctl.toml << 'EOF'
namespace = "k8s.io"
EOF
```

**3. HTTP 私有仓库要显式信任**
Harbor 是 HTTP（没证书），containerd 默认只信 HTTPS，必须显式放行：
```bash
mkdir -p /etc/containerd/certs.d/harbor.127.0.0.1.nip.io:9443
cat > /etc/containerd/certs.d/harbor.127.0.0.1.nip.io:9443/hosts.toml << 'EOF'
server = "http://harbor.127.0.0.1.nip.io:9443"
[host."http://harbor.127.0.0.1.nip.io:9443"]
  capabilities = ["pull", "resolve", "push"]
  skip_verify = true
EOF
# 注意：目录名必须带端口 :9443
```

### nerdctl 常用命令

```bash
nerdctl images                    # 看镜像列表
nerdctl ps                        # 看运行中的容器
nerdctl pull nginx:latest         # 拉镜像
nerdctl build -t 镜像名:标签 .     # 构建镜像
nerdctl push 镜像名:标签           # 推送镜像
nerdctl run -d --name test nginx  # 跑容器
```

### Dockerfile 手写（你的 demo-app 用的）

```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

构建和推送：
```bash
nerdctl build -t harbor.127.0.0.1.nip.io:9443/devops/demo:v1 . --insecure-registry
nerdctl push harbor.127.0.0.1.nip.io:9443/devops/demo:v1 --insecure-registry
```

## 第 3 章：K8s 核心

### 学什么
K8s 是什么、五大组件、Pod/Deployment/Service、Sealos 安装、namespace、污点与容忍。

### 核心概念

**K8s 的灵魂**：声明式 + 控制循环。你声明期望状态（"我要 3 个副本"），它不停对比实际状态，不一致就自动纠正。

**五大组件**：
- etcd：存状态（期望 + 实际）
- API Server：唯一管理入口
- Controller：对比纠正（真正干活的）
- Scheduler：调度选节点
- kubelet：节点上真正跑容器

**Pod / Deployment / Service**：
- Pod：最小调度单位，里面装容器
- Deployment：声明副本数和版本，Controller 保证
- Service：给一组 Pod 固定访问入口，靠标签选择器转发

三者靠**标签**松耦合（如 `app=demo`）。

### 你项目里怎么用的

**Sealos 安装**（你实际执行的）：
```bash
# 安装 Sealos
wget https://github.com/labring/sealos/releases/download/v5.0.0/sealos_5.0.0_linux_amd64.tar.gz
tar -xzf sealos_5.0.0_linux_amd64.tar.gz
mv sealos /usr/local/bin/

# 一键装 K8s（单节点）
sealos run labring/kubernetes:v1.28.0 labring/calico:v3.26.1 --single
```

**namespace 规划**（你的项目）：
- `devops`：Gitea、Harbor、Jenkins、ArgoCD
- `demo`：你的演示应用
- `monitoring`：监控组件
- `ingress-nginx`：Ingress 控制器
- `kube-system`：系统组件

**污点与容忍**：master 节点默认有污点（保护控制面），单节点必须去掉，否则业务 Pod 一直 Pending。Sealos 自动帮你去掉了（`Taints: <none>`）。

### kubectl 常用命令

```bash
kubectl get nodes                        # 看节点
kubectl get pods -n demo                 # 看 demo 命名空间的 Pod
kubectl get pods -A                      # 看所有命名空间的 Pod
kubectl get svc -n demo                  # 看 Service
kubectl get deploy -n demo               # 看 Deployment
kubectl describe pod <pod名> -n demo      # 看 Pod 详情（排障用）
kubectl logs <pod名> -n demo             # 看日志
kubectl logs --previous <pod名> -n demo   # 看崩溃前的日志（关键！）
kubectl apply -f deployment.yaml         # 应用配置
kubectl delete -f deployment.yaml        # 删除
```

## 第 4 章：K8s 网络与存储

### 学什么
Calico/CNI、Ingress/Ingress-nginx、nip.io 域名、PV/PVC/StorageClass/NFS。

### 网络部分

**CNI 与 Calico**：K8s 定了网络标准接口（CNI），Calico 是按这个标准做的网络插件。装上它，Pod 之间才能互相通信。

**Calico 时序问题（你踩过的坑）**：第一次装报 `no matches for kind "Installation"`，是 CRD 还没注册就建资源。**原样重跑一次就成功**。

**Ingress 与 Ingress-nginx**：Ingress 是规则（"域名/路径 → 转发到哪个 Service"），Ingress-nginx 是执行者（站在集群门口的网关）。

**Ingress 端口踩坑（你踩过的坑）**：
- 改 8080 报 `port 8080 is already in use`（被 ingress-nginx 内部占用）
- 8443 被 validating-webhook 占用
- 最终：**HTTP 用 9443，HTTPS 用 8543**
- 排障关键：`kubectl logs --previous`（当前容器日志是空的，崩溃前的日志在 --previous 里）

**hostNetwork**：让 Pod 直接用宿主机网络（IP 和端口）。Ingress-nginx 用了它，这样外部流量直接到服务器端口。

**nip.io 域名**：免配置临时域名。`harbor.127.0.0.1.nip.io` 自动解析到 `127.0.0.1`。你没买正式域名，用这个配合 Ingress 测试。

### 存储部分

**为什么需要存储**：容器重启数据就丢，重要数据要外挂。

**存储三件套**：
- PV：真实存储空间在 K8s 里的登记
- PVC：应用的存储申请单
- StorageClass：自动创建 PV 的中介

**NFS**：底层真正存数据的地方（网络共享文件夹）。

**流程**：Pod 交 PVC → StorageClass 自动在 NFS 上建目录 → 状态变 Bound。

**现状**：装好了但 CI 流水线没完全接上（半自动）。

### ArgoCD（CD 工具）

**你踩过的坑**：
1. 默认走 HTTPS，入口走 HTTP 时要加 `--insecure`：
```bash

```
2. 访问 Gitea 必须用集群内 Service DNS（不能用 127.0.0.1.nip.io，Pod 里解析不通）：

```yaml

    repoURL: http://gitea.devops.svc.cluster.local:3000/gitea/demo-app.git
    path: deploy
  destination:
    server: https://kubernetes.default.svc
    namespace: demo
  syncPolicy:
    automated:
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
```

## 第 6 章：CI/CD 流水线——把整条链路串起来

### 学什么
CI / CD / GitOps / Webhook、完整 8 步流程、v1→v2 升级实战。

### 核心概念

- **CI（持续集成）**：代码提交后自动构建镜像推仓库。工具：Jenkins。金句：**CI 管代码变镜像**。
- **CD（持续部署）**：把镜像自动部署到 K8s 上线。工具：ArgoCD。金句：**CD 管镜像变线上服务**。
- **GitOps**：以 Git 为唯一真相源，改 Git 配置 = 改线上系统。ArgoCD 盯着 Git，发现变了自动同步。
- **Webhook**：代码一提交，自动通知 Jenkins 开始构建（门铃）。

### 你真实做过的 v1→v2 升级

这是项目最有说服力的部分——你完整走过一遍：

```bash
# 1. 修改代码（index.html 里的 v1 改成 v2）
# 2. 构建新镜像
nerdctl build -t harbor.127.0.0.1.nip.io:9443/devops/demo:v2 . --insecure-registry
# 3. 推送到 Harbor
nerdctl push harbor.127.0.0.1.nip.io:9443/devops/demo:v2 --insecure-registry
# 4. 修改 Gitea 里 deployment.yaml 的镜像 tag：v1 → v2
# 5. git commit + push
# 6. ArgoCD 自动检测到变化 → 自动同步 → K8s 拉新镜像 → 滚动更新
```

**你在 ArgoCD 界面上看到的**：状态从 OutOfSync → Synced，Pod 从旧的终止、新的拉起。

### CI 半自动的现状

你诚实标注了：CD 全自动（ArgoCD），CI 半自动（Jenkins 装了但流水线没接）。

**接入规划**（面试能说出来的）：
- Jenkinsfile 里写 pipeline：`checkout → build → push`
- 构建用 kaniko 在集群内跑（不需要 Docker 守护进程，更安全）
- 接上后：git push → Webhook 触发 Jenkins → 自动构建推送 → 自动改 tag → ArgoCD 自动部署

## 第 7 章：监控与排障

### 监控部分

**你在项目里搭过的链路**（node_exporter + Prometheus + Grafana）：

```bash
# ① node_exporter（采集主机指标，每台被监控机器上装）
wget https://github.com/prometheus/node_exporter/releases/download/v1.7.0/node_exporter-1.7.0.linux-amd64.tar.gz
tar -xzf node_exporter-1.7.0.linux-amd64.tar.gz
cd node_exporter-1.7.0.linux-amd64
nohup ./node_exporter --web.listen-address=:9100 &
# 验证：curl localhost:9100/metrics

# ② Prometheus（拉取并存储指标）
# prometheus.yml 里加 job：
#   - job_name: 'node'
#     static_configs:
#       - targets: ['localhost:9100']
nohup ./prometheus --config.file=prometheus.yml &
# 界面：http://localhost:9090

# ③ Grafana（可视化）
nohup ./bin/grafana server &
# 界面：http://localhost:3000，默认 admin/admin
# 添加数据源 Prometheus → 导入面板模板
```

**三层监控框架**：主机层（CPU/内存/磁盘/网络）→ 服务层（进程存活、端口）→ 业务层（请求量、错误率）。

### 排障三板斧（K8s）

```bash
# 第一步：看状态
kubectl get pods -n <namespace>
# 常见状态：Pending（调度不上）、ImagePullBackOff（镜像拉不到）、CrashLoopBackOff（反复崩溃）

# 第二步：看详情
kubectl describe pod <pod名> -n <namespace>
```
