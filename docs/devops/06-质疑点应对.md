# DevOps 项目质疑点应对卡（2026-08-27）

> 针对科杰面试官的两个质疑：
> **① "你就用一个单节点做了这么多东西？"**
> **② "你确定自己会这些技术？"**
> 这两问本质是在测两件事：**真实性**（是不是照着教程/AI 抄的）和**深度**（懂不懂原理）。
> 应对总原则：**不辩解、不吹牛，用"具体数字 + 只有真做过才说得出的细节"让质疑自动消失。**

## 一、质疑①：单节点能跑这么多东西吗？

### 1.1 先背熟你的"资源账"（证明你真跑过、真算过账）

| 组件 | 内存占用 | 备注 |
|------|---------|------|
| 系统本身（Rocky + 内核） | ~1.5G | |
| K8s 控制面（etcd/apiserver/scheduler/controller） | ~2G | 单节点全挤一起 |
| Harbor | ~2G | 关掉 trivy 后降下来了 |
| Jenkins | ~2G | 吃内存大户 |
| ArgoCD | ~0.5G | 很轻 |
| NFS/Calico/Ingress 等 | ~1G | |
| **合计** | **约 9-10G** | 4核16G 的机器，**留了 6G 余量**，够用 |

**你的机器**：阿里云 ECS，`ecs.e-c1m4.xlarge`，4核16G，100G 系统盘，按量付费（¥0.93/小时）。

### 1.2 关键是：你还讲得出"为了省内存做了哪些裁剪"（这才是真的会规划）

| 裁剪决策 | 一句话理由 |
|---------|-----------|
| 用 **Gitea** 不用 GitLab | GitLab 功能全但吃内存好几个 G，单节点扁不住；Gitea 几百 M 就够 |
| **Harbor 关掉 trivy**（漏洞扫描组件） | 扫描组件吃内存，学习环境用不上，关掉能省不少 |
| Harbor 用 **chart 内置 PostgreSQL + Redis**（自包含） | 教程生产版是外部 PostgreSQL/Redis/MinIO，单机资源有限，自包含最省 |
| **Gitea 用 SQLite** 免额外数据库 | 不用再单独起一个数据库组件 |
| 命名规范裁剪 | 参照企业"多地多中心"规范，裁成单数据中心 BJ-DC01 / 可用区 bj-az01，namespace 分 devops / app-dev / monitoring |

### 1.3 标准应答（背熟，30 秒版）

> "确实是一台单节点，4核16G 的 ECS。能装下是因为我把每样东西的内存都算过账：K8s 控制面大概 2G、Harbor 2G、Jenkins 2G、ArgoCD 0.5G，加上系统和网络组件，总共 9-10G，留了余量。而且我做了一堆省资源的裁剪——用 Gitea 不用 GitLab（差好几个 G 内存）、Harbor 关掉 trivy 扫描组件、数据库用内置的不用外部独立部署。所以 16G 跑这套是够的，只是比较紧张，构建镜像的时候要盯着内存。它是**学习验证版**，目的是把链路跑通，不是生产容量规划。"

**追问防护**："那构建镜像时内存不够怎么办？"→ "构建是 CPU/内存峰值操作，我确实遇到过一次。解决思路：构建前先停掉不用的组件（比如把 Harbor 的 UI 缩到 0 副本），构建完再拉起来；或者错峰构建。"

## 二、质疑②：你确定自己会这些技术？

### 2.1 心态先摆正

面试官这么问通常不是要羞辱你，而是：**没做过的人被这么问会慌、会含糊其辞、会吹**。你只要做到"不慌 + 掏出真实细节"，这道题反而是你得分的机会。

**三条铁律**：
1. 被质疑**不要着急辩解**，更不要慌着说自己"都会"
2. 用**具体细节**回应，一个细节顶十句"我会"
3. 被问到不会的，照旧"没实际做过，但我知道原理是……"

### 2.2 你的细节武器库（每个都只有真做过才说得出来，挑 5-6 个反复用）

| # | 细节 | 一句怎么用 |
|---|------|-----------|
| 1 | **K8s 节点不需要 Docker**：装 Sealos 时报 containerd 冲突，因为装 Docker 时带了 containerd.io，Sealos 要自己管 containerd 拒绝复用；卸载 Docker + 清理 `/var/lib/docker`、`/var/lib/containerd` 残留目录后重跑成功 | "所以现在节点上容器运行时是 containerd，排查用 nerdctl，不装 Docker" |
| 2 | **镜像加速要分三套配**：containerd（`certs.d/<域名>/hosts.toml`）、buildkit（`buildkitd.toml`）、Docker（`daemon.json`）是三个独立程序，各配各的；containerd 还能配多个 mirror 故障转移 | "只配一处不生效，我三套都单独配过" |
| 3 | **containerd 有命名空间**：K8s 镜像在 `k8s.io`，nerdctl 默认看 `default`，必须配 `namespace = "k8s.io"` 才看得到集群镜像 | "不配这个，nerdctl images 是空的" |
| 4 | **Gitea 1.22 禁止 root 运行**：创建管理员要 `su -c` 切到 git 用户 | "Gitea 新版安全设计，root 跑会被拒" |
| 5 | **Ingress 端口踩坑**：改 8080 报 `port 8080 is already in use`（被 ingress-nginx 内部占用），8443 被 validating-webhook 占用，最后 HTTP 用 9443、HTTPS 用 8543 | "排查 CrashLoopBackOff 必须看 `kubectl logs --previous`，当前容器日志是空的" |
| 6 | **HTTP 私有仓库要显式信任**：`/etc/containerd/certs.d/harbor.127.0.0.1.nip.io:9443/`（目录名必须带端口）+ `skip_verify=true`，否则拉推都失败 | "containerd 默认只信 HTTPS，HTTP 仓库必须显式放行" |
| 7 | **ArgoCD 默认走 HTTPS**：入口走 HTTP 时给 argocd-server 加 `--insecure`，否则浏览器报 SSL 错误 | "入口协议必须和组件内部协议对上" |
| 8 | **ArgoCD 访问 Gitea 用集群内 Service DNS**：`http://gitea.devops.svc.cluster.local:3000`，不能用 127.0.0.1.nip.io（Pod 里解析不通） | "Pod 之间互访要用 Service DNS 名，这是 K8s 服务发现的规矩" |
| 9 | **ImagePullBackOff ≠ 网络问题**：NFS 制备器报 `repository does not exist`，是镜像地址写错不是网络；先 `nerdctl pull` 验证再 `kubectl set image` 热替换 | "看 describe 的 Events 具体报错文案再判断方向" |
| 10 | **备案拦截是旁路异步扫描**：首次访问能通，刷新后被阿里云网关拦；拦截依据是 HTTP 的 **Host 头域名**（不是端口），换端口没用，最后用 SSH 隧道 + 解析到 127.0.0.1 的 nip.io 域名绕过 | "本地 `ssh -L 9443:127.0.0.1:9443 root@公网IP`，HTTP 封在 SSH 隧道里网关读不到 Host 头" |
| 11 | **拉镜像慢先查带宽**：5Mbps 峰值≈640KB/s，Ingress 镜像拉 140 秒没完成，调高带宽峰值到 100Mbps 就快了（按流量计费，入向免费，调峰值不额外花钱） | "云上排查慢速先看是不是触到带宽上限" |
| 12 | **Calico 安装时序问题**：第一次报 `no matches for kind "Installation"`，是 CRD 还没注册就建资源，原样重跑一次就成功 | "声明式部署遇到 CRD 未就绪的报错，重试往往就过" |

### 2.4 被要求现场写/说的时候（大概率会被考）

**A. 默写一个 deployment.yaml**（你的 demo-app 就是这种结构）：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: demo
  namespace: demo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: demo
  template:
    metadata:
      labels:
        app: demo
    spec:
      containers:
        - name: demo
          image: harbor.127.0.0.1.nip.io:9443/devops/demo:v2
          ports:
            - containerPort: 80
```

**B. 默写构建推送命令链**（CI 核心动作，你手敲过）：

```bash
nerdctl build -t harbor.127.0.0.1.nip.io:9443/devops/demo:v2 . --insecure-registry
nerdctl push harbor.127.0.0.1.nip.io:9443/devops/demo:v2 --insecure-registry
# 改 deployment.yaml 的 tag v1→v2 → git commit + push → ArgoCD 自动同步
```

**C. 说清 ArgoCD Application 关键参数**：

```yaml
spec:
  source:
    repoURL: http://gitea.devops.svc.cluster.local:3000/gitea/demo-app.git  # 集群内 Service DNS
    path: deploy
  destination:
    server: https://kubernetes.default.svc
    namespace: demo
  syncPolicy:
    automated:
      selfHeal: true        # 集群被手动改了会自动改回
    syncOptions:
      - CreateNamespace=true
```

**D. 说清 CI 半自动的规划**（质疑"这算 DevOps 吗"时的应答）：
> "CI 目前是半自动：构建推镜像是手动 `nerdctl build/push`，Jenkins 装好了但流水线没完全接上。我知道怎么接——Jenkinsfile 里 `pipeline { agent any; stages { checkout → build → push } }`，构建阶段用 kaniko 在集群内跑（不需要 Docker 守护进程、更安全），接上后整条链路就全自动了。这是我下一步在做的事。"

## 三、临场心法

1. **被质疑 = 机会**：面试官如果觉得你是假的，通常不会浪费时间追问，直接pass。他会追问，说明他在给你机会证明。
2. **数字和细节最有说服力**：说"4核16G、9-10G 内存、¥0.93/小时"比说"我真的做了"有用一百倍。
3. **不慌的前提是熟**：把 2.2 的细节武器库挑 5-6 个背到能脱口而出，它们就是你的"防伪标记"。
4. **绝对红线**：没做过的（多节点、生产流量、Jenkins 自动化）一律不吹，就说"这是单节点学习版，生产我了解应该怎么做（Q4 那套）"。
