## 五、核心原理总结

### 5.1 WAF工作原理

```
用户浏览器
    ↓ HTTP请求
hosts/DNS解析 → WAF服务器(192.168.121.102:80)
    ↓ WAF检测引擎分析请求
    ├─ 正常请求 → 放行 → 转发给后端Nginx(192.168.121.101:80)
    └─ 恶意请求 → 拦截 → 返回拦截页面
```

### 5.2 为什么WAF要独立部署

1. **减少影响范围**：WAF是关键组件，影响所有业务流量，独立部署避免与业务服务相互影响
2. **避免端口冲突**：WAF需要监听80/443端口，如果和Nginx同机器会冲突
3. **资源隔离**：WAF检测消耗CPU/内存，不抢业务服务器资源
4. **故障隔离**：WAF挂了不影响后端业务服务器，可以快速排查

### 5.3 反向代理模式

- WAF本质上是一个**反向代理**，客户端不直接访问后端服务器
- 所有流量先到WAF，WAF检测后决定放行或拦截
- 上游服务器（Upstream）= 后端真实Web服务器

### 5.4 防护能力

| 防护类型 | 作用 | 对应面板功能 |
|----------|------|-------------|
| 攻击防护 | SQL注入/XSS/代码注入/RCE等 | 攻击防护 |
| CC防护 | 频率限制，防止高频请求刷接口 | CC防护 |
| Bot防护 | 人机验证，防止爬虫/自动化工具 | BOT防护 |
| 身份认证 | 等待室/密码保护 | 身份认证 |

## 九、面试要点

### Q1：WAF是什么？怎么工作的？
**A**：WAF（Web Application Firewall）是Web应用防火墙，通过反向代理模式工作。所有HTTP流量先经过WAF，WAF检测引擎分析请求内容，正常请求放行并转发给后端服务器，恶意请求（SQL注入、XSS、代码注入等）被拦截并返回拦截页面。

### Q2：为什么WAF要独立部署，不和Web服务器放一起？
**A**：
1. 减少影响范围：WAF是关键组件影响所有流量，独立部署避免相互影响
2. 避免端口冲突：WAF需要监听80/443端口，和Nginx同机器会冲突
3. 资源隔离：WAF检测消耗CPU/内存，不抢业务服务器资源
4. 故障隔离：WAF挂了不影响后端业务服务器

### Q3：WAF的高可用怎么实现？
**A**：部署多台WAF，配置完全一致，通过DNS轮询（A记录配多个IP）将流量分配到各WAF节点。任何一台宕机，DNS会剔除故障IP，流量自动转到其他节点。社区版需手动同步配置，企业版有自动配置同步。

### Q4：hosts配置和DNS解析什么关系？
**A**：hosts文件是本地DNS解析，优先级高于公网DNS。本地测试时用hosts模拟DNS解析，把域名指向WAF的IP。生产环境用真实DNS服务器配置A记录，效果相同。

### Q5：你在WAF项目中遇到了什么问题？怎么解决的？
**A**：
1. 内存不足：WAF要求至少1GB空闲内存，虚拟机默认1GB不够，调到2GB解决
2. 端口冲突：hadoop102上Nginx占用了80端口，WAF也要用80，停掉Nginx让给WAF
3. Docker源连不上：官方Docker仓库被墙，换阿里云镜像源解决

### Q6：WAF能防护哪些攻击？
**A**：SQL注入、XSS、代码注入、命令注入、RCE、XXE、路径遍历、后门、暴力破解、CC攻击、爬虫等。除了攻击防护，还有CC防护（频率限制）、Bot防护（人机验证）、身份认证等功能。

### Q7：WAF防护应用里的"上游服务器"是什么意思？
**A**：上游服务器就是后端真实的Web服务器。WAF作为反向代理，把检测通过的请求转发给上游服务器。我们的配置是 `http://192.168.121.101`，指向hadoop101上的Nginx。

#### CDN工作原理
```
用户请求 img.chenshihao.cn/图片.jpg
    ↓ DNS解析到CDN节点（CNAME）
CDN边缘节点
    ├─ 有缓存 → 直接返回图片（快！）
    └─ 无缓存 → 回源OSS拉取 → 缓存 → 返回
```

#### 测试结果
- 直接访问CDN图片URL → 返回AccessDenied（防盗链拦截），说明CDN回源到OSS链路已通
- CDN回源时Referer与OSS防盗链白名单不匹配是已知问题，生产环境需配置CDN回源Referer

#### CDN + OSS架构优势
1. 用户访问图片走CDN缓存，不走OSS源站
2. 省OSS流量费（CDN流量更便宜）
3. 访问速度更快（就近节点）
4. 配合防盗链防止资源被盗用

| 80端口被占用 | WAF的Nginx已占用80端口 | 删除独立Nginx，用Python HTTP服务器 |

## 十二、云端面试要点补充

### Q8：SSL证书的DV、OV、EV有什么区别？
**A**：
- DV（域名验证）：只验证域名所有权，免费，签发快（几分钟），适合个人/测试
- OV（组织验证）：验证企业信息，收费，签发需1-3天，适合企业网站
- EV（扩展验证）：最高级别验证，浏览器显示企业名，收费，签发需3-7天，适合金融/电商

### Q9：OSS防盗链是怎么工作的？
**A**：通过Referer白名单实现。浏览器请求图片时会携带Referer头标识来源页面，OSS检查Referer是否在白名单中。不在白名单的请求返回AccessDenied。配置空Referer不允许可以防止直接复制URL访问。生产环境可配合CDN鉴权或签名URL使用。

### Q10：CDN加速的原理是什么？
**A**：CDN将静态资源缓存到全国各边缘节点，用户访问最近的节点获取内容，减少回源。配置流程：添加加速域名 → 配置源站（OSS/IP/域名） → DNS解析CNAME到CDN节点 → 用户请求自动走CDN。CDN配合OSS可以降低源站流量费用，提升访问速度。

### Q11：SLB负载均衡的作用？
**A**：SLB将流量分发到多台后端服务器，实现高可用（一台挂了另一台顶上）、横向扩容（加机器分担流量）、无感发布（一台一台更新代码用户不中断）。健康检查机制会自动剔除故障服务器。

### Q12：你在云端部署中遇到了什么问题？
**A**：
1. epel-release包冲突：阿里云Linux自带旧版EPEL，用--allowerasing强制更新解决
2. 80端口被WAF占用：WAF的Nginx占用80端口，改用Python HTTP服务器作为后端
3. 域名未备案：阿里云大陆服务器要求域名ICP备案，用HTTPS或IP访问绕过
4. CDN回源Referer不匹配：CDN回源到OSS时Referer与防盗链白名单不匹配，是CDN+OSS防盗链的经典问题
