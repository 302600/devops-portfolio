## 第二步：安装雷池WAF

**对应截图**：第2张（WAF介绍+安装方式）、第3张（一条命令安装）、第4张（安装完成输出账号密码）

### 2.1 WAF安装方式

原始教程介绍了两种部署方式：
- **WAF独立节点部署（推荐）**：WAF单独装一台机器
- **WAF和业务服务器共用一个节点（不推荐）**：资源不够时才用

> **对应截图**：第2张——"雷池WAF介绍"，页面写了"1 WAF独立节点部署（推荐）"和"2 WAF和业务服务器共用一个节点部署（不推荐）"

### 2.2 执行安装命令

在hadoop102上执行（WAF检测点1）：

```bash
bash -c "$(curl -fsSL https://waf-ce.chaitin.cn/release/latest/manager.sh)"
```

> **对应截图**：第3张——终端里显示的安装命令就是这一条，官网说"只需要一条命令即可安装"

执行后会弹出选择菜单：

```
选择你要执行的动作 [ 1.安装 2.升级 3.卸载 4.修复 5.重启 ] (1/2/3/4/5):
```

输入 `1` 选择安装。

> **对应截图**：第3张——终端输出里显示了SafeLine WAF的ASCII艺术字和这个选择菜单

### 2.3 输入安装路径

提示输入安装路径时，输入：

```
/opt/module/waf-leichi
```

> **对应截图**：第4张——终端显示"安装路径"输入框，教程说明"不用创建目录，WAF安装脚本会自动创建，直接提供一个安装路径即可"

### 2.4 等待安装完成

安装过程会自动：
1. 检查Docker和Docker Compose版本
2. 初始化挂载目录
3. 下载.env和docker-compose.yaml
4. 拉取Docker镜像

安装完成后会显示：

```
Initial username: admin
Initial password: xxxxxx（随机生成的密码，记下来！）
https://127.0.0.1:9443/
https://0.0.0.0:9443/
```

> **对应截图**：第4张——终端底部显示了账号密码和访问地址，教程提醒"保存好访问地址和账号密码"

> **⚠️ 重要**：把生成的账号密码记下来！后面登录WAF面板要用。

## 第五步：配置本地hosts解析（替代DNS）

这一步是本地的重点。原始教程用阿里云DNS做域名解析，你用本地hosts文件代替。

### 5.1 理解DNS解析问题

原始教程解释了一个关键问题：当WAF和业务服务器共用一个节点时，如果域名解析走公网DNS，会形成循环重定向。

> **对应截图**：第11张——两个流程图对比"错误解析示范"和"正确解析示范"。错误示范：域名→公网DNS→WAF→公网DNS解析→死循环。正确示范：域名→WAF→容器Hosts解析→直接到服务器IP

### 5.2 配置hosts文件

在你本机（Windows）的hosts文件里加一行：

```
192.168.121.102  web.hadoop101.com
```

> 路径：`C:\Windows\System32\drivers\etc\hosts`
> 意思：访问 web.hadoop101.com 时，直接指向192.168.121.102（WAF节点）

> **对应截图**：第12张——"配置Hosts解析"说明文字。教程说"WAF上游服务器需要在本地通过Hosts文件解析"
>
> **对应截图**：第13张——`cat docker-compose.yaml`输出，红箭头指向 `extra_hosts` 部分，里面配了 `qiuyl.com:47.119.167.81`。你在WAF的docker-compose.yaml里也可以加类似的extra_hosts，把域名指向你的Web服务器IP。

### 5.3 ERR_TOO_MANY_REDIRECTS问题

如果配置不对，浏览器会报"重定向次数过多"错误。

> **对应截图**：第14张——浏览器显示"当前无法使用此页面"，错误码 `ERR_TOO_MANY_REDIRECTS`。这是因为WAF和业务服务器在同一台机器上，端口冲突导致的循环重定向。
>
> **解决方法**：原始教程的方案是把业务服务的端口从80改成81，WAF监听80，上游服务器指向 `http://127.0.0.1:81`。你也可以参考第15张截图。

> **对应截图**：第15张——WAF配置页面，红箭头指向"上游服务器"字段，值是 `http://127.0.0.1:81`。这就是把Nginx改到81端口，WAF占80端口。

原始教程用阿里云DNS的轮询功能，让域名解析到两个WAF IP。本地用hosts的话，可以配两条记录：

在Windows的hosts文件里加两行：

```
192.168.121.102  web.hadoop101.com
192.168.121.103  web.hadoop101.com
```

> **注意**：Windows的hosts文件对同一域名多条记录会轮询解析，和DNS轮询效果类似。

> **对应截图**：第二批发送的第10张——阿里云DNS配置页面，A记录web.qiuyl.com，记录值负载策略选"轮询"，两个IP：47.115.145.225和47.113.103.160。底部说明"指定使用8.8.8.8 DNS服务器来解析"
>
> **对应截图**：第二批发送的第11张——`dig web.qiuyi.com @8.8.8.8` 终端输出，ANSWER SECTION返回两条A记录，两个IP都返回了。红箭头指向47.115.145.225。
>
> **对应截图**：第二批发送的第12张——两次dig分别得到不同IP（47.113.100.236和47.115.146.210），说明轮询生效。文字说明："可以看到，两个节点分别能对外提供服务，这样我们WAF高可用就完成了。"
